# Приложение и сервис - документ экранов

**Утверждён Мишей 2026-09-30** - все восемь решений §14 как предложены; ход работы - §15. Этап 4 плана
(`PLAN.md`): как выглядят и что делают `BBTunnel` (приложение) и `BBTunnelService` (headless) поверх демона
(`DAEMON.md`). Каждое решение: что выбрано и что отброшено. То, что проверяется только на Passport, помечено
**[телефон]**. Tailscale здесь нет - это этап 6.

Протокол демона (DAEMON §3) закрывает всё, что нужно экранам: менять его не придётся.

## 0. Коротко

- Приложение - клиент демона по unix-сокету. Своего хранилища профилей у него нет: профили, ключи и
  состояние туннелей держит демон.
- `NavigationPane`. Главный экран - список подключений с переключателями; тап по строке - страница профиля;
  «Добавить» - импорт одним листом из четырёх источников: файл, QR-код, вставленный текст, «Открыть в Tunnel»
  из другого приложения. Меню приложения - Настройки (хаб), Помощь, Что нового - как в эталонных приложениях.
- Туннелей может быть поднято несколько; второй профиль «весь трафик» - диалог «переключиться?».
- Статистика - только пока открыта страница профиля. Active Frame - состояние без трафика.
- Сервис при загрузке подписывается на события демона и показывает уведомления: «связь потеряна», «служба
  не отвечает», по желанию - «подключено». Демон он не перезапускает: сервис не root.
- Клиент протокола - одна C++-библиотека исходниками в оба проекта, как `core/` в Syno.

## 1. Общее

- **Языки:** английский (база), русский, польский; слой `bb-shared` L10n, как во всех наших приложениях.
  Перевод новой строки - в том же проходе.
- **Вид:** родные контролы Cascades и системная тема. Служебные страницы (хаб настроек, язык, помощь, «что
  нового») - копия эталонов: BBTelega `HelpSheet`, BBHealth `SettingsPage` / `LanguageSettingsPage` /
  `ChangelogSheet`; отступы - из `dimens` bb-shared.
- **Компоненты:** строка с переключателем (`ToggleableListItem`) и строка «свойство - значение»
  (`PropListItem`) уже есть в Syno (первая пришла туда из BBTelega). Предлагаю перенести обе в bb-shared,
  а не заводить третью копию (§14, п. 7).
- **Экран Passport** квадратный: строки списка компактные, в две строки текста.

## 2. Связь с демоном

**Решение: общий класс `DaemonClient` (C++, `QLocalSocket`)**, исходниками в приложение и сервис -
каталог `Tunnel/client/` с `.pri`, как `core/` в Syno.

- **Сокет:** `data/daemon.sock` в песочнице приложения (у сервиса та же песочница). Демон создаёт его от
  имени приложения (`--owner`), права `0600`.
- **Подключение:** при обрыве - повтор через 1, 2, 5, 10, 30 с. После каждого подключения - `hello` (версия
  демона и протокола, §9).
- **Запросы и ответы:** запросы идут с `id=`, ответы разбираются по нему; события приходят сигналами.
  Разбор и сборка блоков `ключ=значение` - сам `bt_proto.c` демона: C без ввода-вывода, уже с тестами и
  фаззером, общий для демона, `btctl` и клиента. Поверх него - тонкий слой на `QLocalSocket`. Незнакомые
  ключи пропускаются. Лимиты демона: имя - 1-64 байта, `.conf` - до 192 КБ, блок - до 256 КБ.
- **Модель для QML** - список профилей:
  - из `profile.list`: `id`, `name`, `type`, `order`, `always_on`, `state`;
  - из событий `tunnel`: `reason`, `detail`;
  - из событий `stats`: `rx_bytes`, `tx_bytes`, `last_handshake_time_sec`, `endpoint`.

  Модель обновляют события `tunnel`, `profile` (`added` / `updated` / `deleted`) и `stats`. Подробности
  профиля - `profile.get` при открытии его страницы.
- **Ключи:** приватный ключ проходит через приложение только при импорте. Текст `.conf` уходит в демон и
  затирается в памяти; на диск приложение его не пишет, назад демон его не отдаёт (DAEMON §2).

Отброшено: `QProcess` + `btctl` (процесс на каждый запрос и никаких событий); свой парсер на Qt (второй
разбор того же формата, который пришлось бы тестировать отдельно); свой кеш профилей в приложении
(второй источник правды, который расходится с демоном).

## 3. Главный экран - «Подключения»

```
+------------------------------------------+
| Tunnel                                   |  TitleBar
+------------------------------------------+
| Дом                              [  on ] |  ToggleButton
| AmneziaWG - подключено                   |  (цвет акцента)
|------------------------------------------|
| Работа                           [ off ] |
| WireGuard - выключено                    |
|------------------------------------------|
| NAS                              [  on ] |
| WireGuard - сервер не отвечает           |  (красным)
+------------------------------------------+
| [+ Добавить]                       [...] |  ActionBar
+------------------------------------------+
```

- **Строка:** имя профиля, под ним тип и состояние (тексты - §7).
- **Переключатель** включает `tunnel.up`, выключает - `tunnel.down`. Он показывает «туннель в работе у
  демона» (connecting / up / reconnecting / error), а не «рукопожатие прошло»: иначе он дёргался бы при
  каждом переподключении. При ошибке переключатель остаётся включённым, строка красная; выключение убирает
  и ошибку.
- **Тап** по строке открывает страницу профиля (§4). **Долгое нажатие** - меню: Подключить / Отключить,
  Переименовать, Всегда включён, Удалить.
- **Порядок** - `order` демона; новый профиль встаёт в конец. Перестановки в v1 нет.
- **Список короткий** (профилей единицы) - `Repeater` из bb-shared в `ScrollView`, а не `ListView`:
  переиспользованные делегаты `ListView` держат отрисовку прошлой строки, и переключатель показывал бы
  чужое состояние.
- **Пустой список:** «Профилей пока нет» и три кнопки - Файл, QR-код, Вставить текст.
- **Служба недоступна** (сокета нет или отказ): вместо списка - «Служба туннеля не запущена», одна строка
  пояснения (служба работает от root и стартует при загрузке телефона, подробнее - в Помощи) и кнопка
  «Повторить». Повтор идёт и сам (§2).
- **Второй «весь трафик».** Демон отвечает причиной `conflict`, в `detail` - id профиля, который уже
  держит маршрут по умолчанию. Диалог: «Весь трафик уже идёт через «Дом». Переключиться на «Работа»?».
  Да - `tunnel.down` старого и `tunnel.up` нового. Нет - `tunnel.down` нового: запись с ошибкой у демона
  живёт до `tunnel.down`.
- **Предел демона - 4 туннеля** (`errno` занятости): тост с текстом ошибки.

Отброшено: один большой переключатель «VPN вкл/выкл» с выбором профиля. Он проще, но прячет главное,
ради чего демон держит несколько туннелей: раздельный туннель рядом с полным (DAEMON §10).

## 4. Страница профиля

```
+------------------------------------------+
| Дом                                      |  TitleBar
+------------------------------------------+
|  Подключено                              |  крупно
|  Получено 12,4 МБ     Отправлено 1,1 МБ  |  пока страница открыта
|  Рукопожатие 38 с назад                  |
|  Сервер сейчас 203.0.113.7:51820         |
|-- Профиль -------------------------------|  Header
|  Тип              AmneziaWG              |
|  Публичный ключ   3gFz...Q=              |  выделяемый текст
|  Адреса           10.8.0.2/32, fd00::2   |
|  DNS              10.8.0.1               |
|  Сервер           vpn.example.com:51820  |
|  Маршруты         весь трафик            |
|  MTU              1380                   |
+------------------------------------------+
| [Отключить]                        [...] |  ActionBar
+------------------------------------------+
```

- **Состояние** крупно; при ошибке, `resolve` или `handshake` - причина и подсказка (§7).
- **Статистика** (`watch stats=1`, §8) - только пока страница на экране. Время последнего рукопожатия
  считается из `last_handshake_time_sec` по часам телефона. «Сервер сейчас» - адрес, по которому пир
  ответил на самом деле (после DNS и роуминга).
- **Свойства** - из `profile.get`:
  - тип, публичный ключ (выделяемый текст - для копирования), адреса, DNS и домены поиска;
  - сервер как в `.conf` - по строке на каждого пира;
  - маршруты: «весь трафик» при `0.0.0.0/0` / `::/0`, иначе «N сетей» и список первых 64;
  - MTU и порт - если заданы.
- **Действия:**
  - Подключить / Отключить - в ActionBar;
  - Переименовать - `SystemPrompt`, `profile.update name=`;
  - Заменить конфигурацию - тот же лист импорта (§5), `profile.update conf=`. Если туннель поднят, новая
    конфигурация действует со следующего подключения: предложить переподключить;
  - Всегда включён - галка, `settings.set always_on=` (по одному профилю каждого вида: WireGuard или AmneziaWG и
    Tailscale; новый занимает место своего вида, повторный выбор снимает - `always_off=`);
  - Удалить - подтверждение, `profile.delete` (поднятый туннель демон опустит сам).

Не в v1: экспорт и «поделиться конфигурацией» (демон `.conf` не отдаёт - DAEMON §2), QR с профилем,
создание профиля с нуля с генерацией ключей.

## 5. Импорт

**Решение: один лист «Новый профиль» для всех источников.**

```
+------------------------------------------+
| [Отмена]    Новый профиль    [Добавить]  |  Sheet
+------------------------------------------+
|  Имя  [ vpn.example.com                ] |
|  Конфигурация из файла home.conf, 18 строк
|  [Показать и изменить текст]             |
|                                          |
|  Строка 7: PrivateKey - не ключ          |  ошибка демона, красным
+------------------------------------------+
```

- **Источники:**
  1. **Файл** - `FilePicker` с фильтром `*.conf` и `*.txt`. Имя профиля - по имени файла.
  2. **QR-код** - страница камеры с распознаванием QR (`Camera` + `BarcodeDetector` из
     `bb.cascades.multimedia`) **[телефон]**. В QR лежит текст `.conf` - так делают WireGuard и Amnezia.
     Имя по умолчанию - хост сервера из `Endpoint`.
  3. **Вставить текст** - редактор сразу открыт, рядом кнопка «Из буфера».
  4. **«Открыть в Tunnel»** из других приложений: `.conf` из менеджера файлов, почты, мессенджера. Нужен
     invoke target на `bb.action.OPEN` / `bb.action.VIEW` с расширением `conf` **[телефон: какой MIME
     дают почта и мессенджеры]**. Открывается тот же лист.
- **Текст конфигурации** для файла и QR свёрнут («Показать и изменить»): приватный ключ не мелькает на
  экране зря. Для вставки редактор открыт сразу. Шрифт моноширинный.
- **Проверяет демон** при `profile.import`. Ошибка с номером строки встаёт под текстом, лист не
  закрывается, опечатку можно поправить на месте.
- **После импорта** лист закрывается, профиль появляется в списке (событие `profile added`), тост «Профиль
  добавлен» с кнопкой «Подключить». Поле текста очищается.
- **Файл с ключом** остаётся, где лежал. Об этом говорит Помощь; сами ничего не удаляем.
- **Ключи AmneziaVPN** - *пересмотрено 2026-09-30 (Миша): делаем сразу, а не «не в v1».* Текст
  `vpn://...`, файл `.vpn` (так их сохраняет AmneziaVPN; фильтр выбора файла и «Открыть в Tunnel» его
  берут) и серия QR-кодов AmneziaVPN. Ключ превращается в `.conf` в приложении
  (`client/gui/AmneziaKey`), дальше обычный путь: лист, демон, ошибки со строкой. Демон про ключи не
  знает. Формат взят из клиента AmneziaVPN (`refs/amnezia-client`, GPL - только читали):
  - ключ - JSON сервера после `qCompress` (4 байта размера big-endian + zlib), base64url без `=`, после
    `vpn://`. Разжимаем сами через zlib с потолком 1 МБ: `qUncompress` растит буфер без предела;
  - QR: сжатый JSON частями по 850 байт, каждая - base64url от `QDataStream`: `qint16 1984`, `quint8`
    число частей, `quint8` номер, `QByteArray`. AmneziaVPN сам листает части раз в секунду; сканер
    собирает их и пишет «часть 2 из 3»;
  - соединение - уже готовый `.conf`: `containers[]` -> `amnezia-awg2` / `amnezia-awg` /
    `amnezia-wireguard` -> `awg` / `wireguard` -> `last_config` (строка JSON) -> `config`. Сначала
    `defaultContainer`. Нет текста - собираем из полей (`client_priv_key`, `client_ip`, `server_pub_key`,
    `psk_key`, `hostName`, `port`, параметры AWG);
  - DNS в тексте оставлен как `$PRIMARY_DNS`, `$SECONDARY_DNS`: подставляем `dns1` / `dns2` ключа, если
    это IPv4, иначе 1.1.1.1 / 1.0.0.1 - как AmneziaVPN. Строки без значения выкидываем. MTU в тексте
    нет: AmneziaVPN на телефоне берёт 1280, мы тоже;
  - имя профиля - `description` ключа (имя сервера в AmneziaVPN), затем `name`, `hostName`;
  - не соединение - говорим почему: ключ подписки (AmneziaFree / Premium: `api_config`, `auth_data`,
    `config_version`; подключение каждый раз приходит с серверов Amnezia), ключ полного доступа (логин
    SSH сервера), ключ других протоколов (OpenVPN, XRay... - перечисляем), повреждённый или обрезанный.
- **Разрешения** в `bar-descriptor.xml`: `access_shared` (файлы), `use_camera` (QR).

Отброшено: ручной ввод по полям (ключи, адреса, сервер). На экране телефона он долгий, а все сервисы и
панели отдают готовый `.conf`. Кому надо вручную, вставит текст и поправит.

## 6. Настройки и служебные страницы

**Меню приложения** (свайп сверху): Настройки, Помощь, Что нового - как в Syno и BBHealth
(`SettingsActionItem`, `HelpActionItem`, `ActionItem`).

**Хаб настроек** - строки, каждая открывает свою страницу (образец BBTelega / BBHealth):
- **Подключение.** «Всегда включён»: две `RadioGroup` (`components/AlwaysOnRadios.qml`) - WireGuard и AmneziaWG,
  Tailscale; в каждой «Нет» и профили этого вида, вида без профилей нет на экране; `settings.get` / `settings.set
  always_on=`, `always_off=`. Пояснение: выбранные профили поднимаются при запуске службы (при загрузке телефона) и
  держатся при смене сети. Kill switch не показываем: демон v1 его не выполняет (DAEMON §8).
- **Уведомления** - три переключателя сервиса (§11).
- **Язык** - страница bb-shared L10n, как в BBHealth.
- **Диагностика:**
  - версии приложения и службы (`daemon` и `proto` из `hello`);
  - журнал службы - последние 200 строк (`log.tail`), выделяемый текст, «Обновить»;
  - «Поделиться журналом» - журнал цикла запуска (`misc/bbtunneld-boot.txt` и `.old.txt`, 2026-10-15), файлы
    `data/logs/daemon.txt` и `daemon.1.txt`, журнал сервиса. Текущий журнал, которого нет, и любой, который
    не открылся, - строкой с причиной, а не молчаливым пропуском. Шаринг - только из QML (`Invocation`), как
    везде;
  - «Перезапустить службу» - `daemon.restart` с подтверждением: туннели опустятся на несколько секунд.
    Пока работает демон другой версии (ждёт перезагрузки, §9), кнопка неактивна, а над ней - почему.
  - «Подробный журнал службы» (2026-10-16) - переключатель `log.debug`: включает отладочные строки демона
    на 30 минут, потом демон выключает их сам. Подпись: пока выключено - «Для разбора сбоев. Выключится
    сам через 30 минут; журнал службы никогда не занимает больше 512 КБ», пока включено - «Включён до
    ЧЧ:ММ, потом выключится сам». Состояние спрашивается при открытии страницы, по «Обновить» и после
    переподключения к демону. Виден, только пока служба на связи.
  - Журналы и место: журнал демона - два файла по 256 КБ, сервиса - тоже (размер проверяется на каждой
    строке, не только при запуске сервиса - до 2026-10-16 `service.txt` рос, пока сервис работал), цикла
    запуска - 64 КБ и `.old`. Приложение в файл не пишет.

**Помощь** - `HelpSheet` по образцу BBTelega:
- что это за приложение и что ему нужно: телефон с root, служба запускается при загрузке;
- как добавить профиль;
- что значат состояния и причины;
- AmneziaWG из России;
- профиль без `DNS=` - запросы идут в DNS сети, мимо туннеля;
- файл с ключом после импорта;
- карточка «кофе» из bb-shared.

**Что нового** - `ChangelogSheet` (`changelog.json` + `_ru` + `_pl`), как в BBHealth.

## 7. Состояния и причины - тексты

Причины - из `reason` демона, подробности - из `detail`.

| Состояние / причина | На главном | На странице профиля |
|---|---|---|
| `down` | выключено | Выключено |
| `connecting` | подключение... | Подключение... |
| `up` | подключено | Подключено |
| `reconnecting` | переподключение... | Переподключение: сеть сменилась или сервер замолчал |
| `no_network` | нет сети | Нет сети - туннель ждёт её, трафик мимо не пойдёт |
| `resolve` | имя сервера не находится | Имя `<detail>` не находится. Проверьте адрес сервера |
| `handshake` | сервер не отвечает | Сервер не отвечает: неверный ключ, адрес или протокол. Если вы в России, попробуйте профиль AmneziaWG |
| `conf` | ошибка в конфигурации | `<detail>` (со строкой) |
| `conflict` | - (диалог, §3) | - |
| `tun` | не удалось создать туннель | `<detail>` |
| `route` | не удалось поставить маршруты | `<detail>` |

## 8. Статистика и события

- **События состояния** (`watch`) - всегда, пока приложение запущено: из них живут список и Active Frame.
- **Статистика** - `watch stats=1` на том же соединении, только пока открыта страница профиля и
  приложение не свёрнуто (`Application.thumbnail` / `fullscreen`). Иначе `watch stats=0`: раз в секунду
  демон тогда телефон не будит (DAEMON §3).

## 9. Старый демон после обновления

Переустановка `.bar` подменяет бинарник, а работает прежний демон (DAEMON §12). Приложение сравнивает на
`hello` версию демона со своей (они из одной сборки):
- **Отличается** - демон **не** перезапускается (2026-10-15, решение Миши: обновление - с перезагрузкой).
  На телефоне копия демона, сделанная после загрузки, не запускается (`Operation not permitted`), так что
  `daemon.restart` оставил бы телефон без службы до перезагрузки. Цикл запуска кладёт новую копию сразу,
  при работающем старом демоне, и она стартует со следующей загрузкой. Приложение говорит тостом, раз на
  соединение: «Служба туннеля обновится после перезагрузки телефона». В «Диагностике» над «Перезапустить
  службу» строка «Новая служба туннеля запустится после перезагрузки телефона. До тех пор работает
  прежняя.», а сама кнопка неактивна.
- **`proto` демона новее нашего** (старое приложение) - работаем как есть: незнакомые ключи пропускаются.
- **`BT_VERSION`** (`daemon/src/bt_version.h`) поднимается при каждой правке демона: иначе приложение не
  отличит старый демон от нового, и «Перезапустить службу» после обновления оставила бы телефон без службы.

*До 2026-10-15:* при другой версии и без поднятых туннелей - сразу `daemon.restart`, с туннелем - диалог
«Служба обновлена. Перезапустить?». Работало бы, если бы новая копия запускалась без перезагрузки.

## 10. Active Frame

Свёрнутое приложение: имена и состояния поднятых туннелей (до трёх строк), иначе «Не подключено». Без
трафика: статистика в свёрнутом виде выключена. Обложка пассивная - привязана к модели, без таймера (как в
BBTelega и BBTube). **[телефон]** - симулятор рисует обложки чёрными.

## 11. Сервис BBTunnelService

- **Запуск:** при загрузке (`bb.action.system.STARTED`), после установки и обновления
  (`bb.action.system.UPDATED`), по `START` от приложения. Всё это и `_sys_headless_nostop` уже есть в
  `bar-descriptor.xml`.
- **Работа:** тот же `DaemonClient`, `watch` без статистики, переподключение (§2). Своё у сервиса - только
  решение, когда уведомлять.
- **Уведомления** (`bb::platform::Notification`, в Hub; тап открывает приложение на этом профиле). Один
  ключ уведомления на профиль: новое заменяет старое, Hub не засоряется.
  1. **Связь потеряна: «Дом»** (по умолчанию вкл) - `reconnecting` или ошибка дольше 30 с, с причиной.
     Переходы при смене сети короче - их не показываем. Когда связь вернулась - «Подключено: «Дом»» на
     месте прежнего.
  2. **Служба туннеля не отвечает** (по умолчанию вкл) - сокет пропал и не вернулся за 60 с, или не
     появился за 2 минуты после загрузки (с хуком root v4 - за 16 минут: root приходит поздно).
  3. **Пока подключено** (по умолчанию выкл) - одно уведомление, пока поднят хоть один туннель; снимается
     при отключении. Это единственный системный знак «VPN включён»: значка VPN для чужого туннеля у BB10
     нет.
- **Настройки уведомлений** - `QSettings` в общей песочнице. Сервис перечитывает их при каждом решении
  (это дёшево), отдельный канал «приложение -> сервис» не нужен.
- **Чего сервис не делает:** не перезапускает демон (он не root), не хранит профили, не поднимает
  always-on (это делает сам демон).
- **Автозапуск на root v4** (2026-11-08) - `client/service/RootAutostart`, при каждом старте сервиса, без кнопки:
  ставит хук загрузки через `__root` (DAEMON §12). Обёртки не видно (v2) - ничего не делает. Итог - строки
  `[autostart]` в журнале сервиса и `install:` в `misc/bbtunneld-boot.txt`.
- **Журнал** - `data/logs/service.txt`, уходит вместе с журналом службы в «Поделиться журналом». С 2026-11-09 там же
  журнал ГУИ `data/logs/gui.txt` (`client/FileLog`, общий код с сервисом): один файл `misc/tunnel-log.txt` - журнал
  запуска, демон, сервис, ГУИ.
- **Память:** лимит headless - 3 МБ, с `_sys_headless_xlarge` (есть в дескрипторе) - 30 МБ. Сервис маленький.

**[телефон]:** уведомления из headless-сервиса и тап по ним; переживает ли сервис остановку приложения.

Отброшено: общее хранилище приложения и сервиса с Beacon, как в Syno. Там сервис синхронизирует данные;
здесь всё состояние у демона, и оба - просто его клиенты.

**Что этот тест нашёл и что исправлено** (каждое падало в первом прогоне и проходит после исправления):
- **клиент не переподключался после неудачной попытки.** Qt 4.8 и 5 шлют `error()` раньше, чем сокет
  становится «не подключён», а мы смотрели на его состояние - и новой попытки не планировали. На телефоне
  приложение или сервис, стартовавшие раньше демона, так и не подключились бы; после падения демона -
  тоже;
- **always-on после удаления его профиля** оставался в клиенте: демон сбрасывает его молча, клиент теперь
  перечитывает настройки на `profile deleted`;
- **сервис не видел смену одной причины.** «Подключение», которое не приходит, остаётся в том же
  состоянии и только получает причину - «не удаётся подключиться» не приходило никогда. Теперь сервис
  слушает любое изменение профиля (`ProfileList::profileChanged`);
- **сервис не видел переключателя «пока подключено»,** пока приложение ни разу не сохранило настроек: не
  было каталога настроек и следить было не за чем. Теперь каталог создаётся;
- **«Туннель включён» оставался после падения демона.** Теперь убирается, как только демона нет;
  «подключено» на месте «потеряна» уходит при отключении и удалении профиля;
- **30 с «потеряна связь» считались по грубому 5-секундному таймеру,** который мог сработать чуть рано и
  отложить уведомление на круг. Теперь одноразовый таймер ставится ровно на срок;
- **демон после смены сети сразу возвращал «подключено»:** рукопожатие до смены моложе 180 с. Теперь
  после смены сети «переподключение» держится до рукопожатия или до пакета от сервера (DAEMON §7);
- **ключ в новом профиле не подключался.** После перезапусков метки времени профиля уходят вперёд часов
  (DAEMON §9), сервер помнит самую новую, а новый профиль с тем же ключом начинал по часам. Теперь у демона
  общий «пол» меток (DAEMON §9).

## 16. Art - иконки, сплэши, стор (2026-10-16)

Всё делает bb-shared `tools/gen-art.js`. Глиф - стоковый BB10 `ca_wifi_0_locked.png` (81 px, серый, лежит в
`BBTunnel/`), перерисованный в SVG по его же пропорциям: `BBTunnel/tools/wifi-lock.svg`, сверен с оригиналом
на 81 px (средняя разница 2 %). Вектор чёткий и на сплэше 1440, а PNG пришлось бы растягивать в 7-8 раз;
цвет глифа - белый (`gen-art` берёт у глифа только прозрачность). Палитра - с образца Миши: тёмный индиго,
фиолетовый, голубые линии. Фон - градиент с дорожками-шинами (`--traces`): каналы от краёв к кольцу вокруг
глифа, по ним бегут данные.

```bash
cd Tunnel/BBTunnel

    --traces 9 --trace-color "#2fd0ff" --icon-scale 0.5

node ../../bb-shared/tools/gen-art.js --colors "#12055a,#26108c@55%,#3b1fc2" --glyph tools/wifi-lock.svg \
    --traces 9 --trace-color "#2fd0ff" --icon-scale 0.5 --only store --title Tunnel
```
