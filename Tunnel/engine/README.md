# engine

Движок WireGuard / AmneziaWG на C, sans-IO: ядро протокола без ввода-вывода, крипта через OpenSSL 3.5.8
из `bb-shared/net` (его собирает `bb-shared/net/deps/build-net.sh` в `/root/bbnet-deps`). Собирается
вне Momentics (WSL): кросс-сборка gcc 9.3 под BB10 и сборка под Linux для тестов.
План и журнал - `../docs/PLAN.md`, этапы 2 и 5.

## Сборка и тесты

```
MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu -u root -- bash /mnt/e/dev/momentics-projects/Tunnel/engine/build.sh [host|cross|all]
```

`host` - тесты на ПК под ASan+UBSan против системного OpenSSL 3; `cross` - те же исходники под BB10 со
статическим OpenSSL 3.5.8 (бинарники в `build/bb10/`). Перед сдачей гонять `all`: часть ловушек
заголовков QNX видна только кросс-сборке (см. ниже про `stdint.h`).

`bench [секунды]` - замер на одном ядре (`test/bench/wg_bench.c`, -O2 без санитайзеров): рукопожатие,
шифрование и расшифровка пакетов по 1400 байт - обычные и через AmneziaWG 3.x (префикс 20 байт, тип
из диапазона, защита заголовка, паддинг 0-64), поиск в AllowedIPs на 3000 префиксов. На ПК
(2026-09-29/30): рукопожатие 0,33 мс, шифрование 16,5 Гбит/с, шифрование плюс расшифровка 7,6-8,4
Гбит/с, то же через AmneziaWG 5,0 Гбит/с, поиск 88-96 нс.
`cross` кладёт `wg_bench` и для телефона - цифры Passport туда же, когда будут.

Векторы рукопожатия пишет вторая реализация на Python (нужен `python3-cryptography`, в WSL он есть):

```
python3 engine/test/vectors/gen_noise_vectors.py > engine/test/vectors/kat_noise.h
```

Перегенерировать только при смене входных данных: C-тесты сверяют с ними байты сообщений и ключей.
Векторы защиты заголовка AmneziaWG - `test/vectors/gen_awg_vectors.py` (печатает строки, которые
вписаны в `test_awg.c`).

Совместимость с ядерным WireGuard Linux (нужны модуль `wireguard` и `wireguard-tools`; временный
интерфейс `tuntest0` создаётся на время прогона и удаляется при любом выходе):

```
MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu -u root -- bash /mnt/e/dev/momentics-projects/Tunnel/engine/test/interop/run.sh [soak]
```

`test/interop/wg_interop.c` - движок на настоящем UDP-сокете с циклом на `poll`, как у будущего демона,
только без tun: эхо ICMP внутри туннеля он делает и отвечает на них сам. Сценарии: рукопожатие от нас
(IPv4 и IPv6), рукопожатие от ядра (ядро пингует наш адрес), и с `soak` - 140 секунд со сменой ключей.
Сообщения он считает по каноническому типу, который ставит движок, так что с любым кодеком.

Совместимость с amneziawg-go - тот же харнесс против эталона AmneziaWG в userspace (интерфейс
`awgtest0` на время прогона), профили `awg1` / `awg2` / `awg3`, по умолчанию все:

```
MSYS_NO_PATHCONV=1 wsl.exe -d Ubuntu -u root -- bash /mnt/e/dev/momentics-projects/Tunnel/engine/test/interop/run_awg.sh [awg1|awg2|awg3 ...] [soak]
```

amneziawg-go собирается из `refs/` в каталог прогона Go >= 1.25; в WSL стоит Go 1.27.1 в
`/usr/local/go` (tarball с go.dev, сумма сверена; 2026-09-30), скрипт находит его сам. Модули Go
скачиваются при первой сборке. `awg` из `refs/amneziawg-tools` собирается обычным `make`
(v3.1.20260812). Ловушка: `go build` идёт с `-buildvcs=false` - клон лежит на диске Windows с чужим
владельцем, git под root в WSL отказывается его читать («dubious ownership»), и сборка падала на
VCS-метке, которая никому не нужна.

## Правила для следующих слоёв

- Время и случайность приходят снаружи: `now_ns` - монотонные наносекунды, `wg_rng` - источник байтов
  (пустой = OpenSSL). Тесты подменяют RNG сценарием, и рукопожатие воспроизводится байт в байт.
- Сообщения живут в канонической раскладке WireGuard. Поле типа ставит кодек (WireGuard или AmneziaWG)
  до mac1; `wg_noise` поле типа и маки не читает, `wg_cookie` считает маки по байтам как на проводе.
- Таблицы пиров и индексов - у владельца (движка). `wg_noise` получает и отпускает индексы через
  upcall-ы, `wg_noise_begin_session` передаёт индекс сессии.
- Функции возвращают 1 при успехе и 0 при отказе (как OpenSSL). Неудачный consume не меняет состояние
  пира: мусор из сети не должен ломать рукопожатие. Расшифровка data-сообщения вдобавок говорит,
  почему отбросила (`wg_recv.drop`).
- Окно повторов сдвигается только после проверки тега: поддельный счётчик окно не двигает.
- Демон крутит устройство тремя вызовами: `wg_device_receive` (датаграмма), `wg_device_send` (пакет из
  tun), `wg_device_tick` (время; возвращает ближайший дедлайн для `poll`). Отвечает устройство через
  upcall-ы `send` / `deliver` / `wall_clock`: они синхронные, буфер живёт только на время вызова, и
  обратно в устройство из них звать нельзя.
- Владелец, который сам выбирает путь к пиру (Tailscale через DERP; так magicsock Tailscale ведёт
  wireguard-go), задаёт необязательный upcall `send_peer(ctx, пир, to, ...)` - на тех же правилах, что
  `send`. Задан - через него уходит всё, что идёт конкретному пиру: initiation и response, данные и
  keepalive, датаграммы кодека перед initiation (I-пакеты и мусор AmneziaWG); `to` - endpoint пира.
  Cookie reply отвечает адресу, а не пиру (пир ещё ничем не доказан), - он по-прежнему через `send`. Не
  задан - всё как было.
- Endpoint такого пира - постоянная метка `WG_EP_OWNER` (адрес и порт нули), и ту же метку владелец
  передаёт как `src` всего, что принял от таких пиров. Метка - полноценный endpoint: «нет endpoint -
  не слать» её не задевает, датаграммы перед initiation идут. Роуминг (`heard`) сравнивает метку с
  меткой и ничего не двигает: где пир на самом деле, знает только владелец, и ретранслятор, выдавший
  пакет одного пира за пакет другого, не уведёт пира на чужой путь (пира всё равно находит индекс).
  Окно UDP AmneziaWG при метках не сбрасывается и только растёт - как в мобильных сборках эталона;
  путь владельца должен пропускать датаграммы такого размера (DERP везёт до 64 КиБ). «Под нагрузкой»
  для меток смысла не имеет - cookie привязан к адресу, а метка у всех одна: такой владелец держит
  `under_load` выключенным, иначе его `send` получит cookie reply с `to` = метка. Устройству, где все
  пиры с метками, `send` можно не задавать вовсе: всё нужное уходит через `send_peer`.
- Таймер - это дедлайн в монотонных наносекундах (`WG_NEVER` - не взведён). Времена протокола -
  `wg_timing`: диапазоны целых секунд (AmneziaWG 3.x), по умолчанию одиночные значения WireGuard;
  менять через `wg_device_set_timing` (заодно обновит срок жизни ключей пиров). Где значение тянется
  из диапазона заново, а где берётся край, - как в `timers.go` amneziawg-go: повтор initiation -
  случайное из RekeyTimeout, ограничение частоты - его низ; новое рукопожатие - верх KeepaliveTimeout
  плюс случайное RekeyTimeout; ключи живут до верха RejectAfterTime, стираются через 3 его верха;
  число попыток тянется заново на каждое новое рукопожатие. Одиночное значение случайность не тратит -
  прогоны тестов со сценарным RNG от диапазонов не поехали.
- Keepalive - пустой пакет ИЛИ пакет с нулевым первым байтом: AmneziaWG добивает keepalive нулями
  (ContentPaddingAddition, RandomTrailers), а IP-пакет с нуля не начинается. Правило общее для всех
  кодеков, как в amneziawg-go.
- Кодек узнаёт о подлинных сообщениях через `authentic` (с признаком смены адреса пира) - только
  так, никогда по сырым датаграммам: окно UDP AmneziaWG (граница хвостов и случайного паддинга)
  растёт от подлинных данных и наших отправок и сбрасывается на 500 при переезде пира. В эталоне
  «переезд» сравнивает указатели на endpoint, а стандартный bind создаёт новый на каждую датаграмму -
  там окно сбрасывается после каждой пачки, в мобильных сборках (роуминг выключен) - никогда. У нас
  то, что эталон имел в виду; окно одно на устройство (профили AmneziaWG - один сервер).
- DisableCookies (AmneziaWG) выключает «под нагрузкой» целиком: ни mac2, ни cookie reply, как в
  amneziawg-go после `b5928ef`.
- Паддинг, который просит кодек, устройство урезает до своих буферов (`wg_device_padding`): кодек не
  может переполнить `scratch`.
- Случайность «для провода» (префиксы, хвосты, мусор, байты I-пакетов, выборы из диапазонов) кодек
  AmneziaWG берёт из своего потока ChaCha20 под ключом из OpenSSL, ключ меняется каждый 1 МиБ - как
  arc4random. Замер показал, что `RAND_bytes` три раза на пакет съедал 1,3 из 1,6 мкс кодека
  (стало 0,26 мкс, из них защита заголовка 0,18). Эти байты уходят в открытую, им нужна только
  неотличимость от случайных; ключи, cookie и индексы по-прежнему из OpenSSL. Подключённый к
  устройству RNG (тесты) кодек использует как есть - сценарии по-прежнему решают каждый байт. При
  приёме блок 0 ключевого потока защиты заголовка считается один раз: и маска поля типа, и
  заголовок данных берутся из него.
- Таблицы индексов нет: индекс ищется по рукопожатиям и ключам пиров, линейно по числу пиров. Для
  телефона с парой туннелей это правильно. Владелец, который знает отправителя (кадр DERP называет его
  ключ, а ключ - пира), зовёт `wg_device_receive_from(d, пир, ...)`: индекс ищется только у этого пира,
  за O(1) вместо обхода сотен пиров Tailscale (лишь ответ на initiation один раз обходит всех: свежий
  индекс должен быть свободен у любого пира, иначе обычный приём найдёт по нему чужие ключи), а
  сообщение не от рукопожатия или ключей этого пира отвергается до того, как тронет чьё-то состояние
  (initiation под чужим ключом - прямо в `remote_get`; для данных `last_drop` = `WG_DROP_UNKNOWN_INDEX`).
- Маршрутизация - дерево AllowedIPs в устройстве: исходящий пакет идёт тому пиру, чей префикс точнее
  всех совпал с адресом НАЗНАЧЕНИЯ; входящий доставляется, только если его ИСТОЧНИК тем же поиском ведёт
  к пиру, от которого он пришёл. Узлы дерева даёт владелец (`wg_device_set_allowedips_storage`,
  n префиксов - не больше 2n узлов); без них любой `wg_peer_allow` вернёт 0. Не хватило узлов
  (`wg_peer_allow` вернул 0 на живой таблице - netmap вырос) - `wg_device_grow_allowedips` переносит
  таблицу в больший пул владельца, хоть на ходу: узлы ссылаются друг на друга индексами, поэтому это
  копия на те же места, префиксы и ответы поиска не меняются. Новый пул - отдельный блок (не
  `realloc` старого: старый читается во время переезда), может прийти с мусором - движок его
  обнуляет; старый после этого возвращается владельцу (`*old`).
- Все причины отказа от пакета - одно перечисление `wg_drop_reason` в `wg_msg.h`.
- Всё, что уходит на провод и приходит с него, идёт через кодек устройства (`wg_codec`): `stamp`
  пишет поле типа ДО маков, `wrap` строит датаграмму вокруг готового сообщения, `before_initiation`
  шлёт пакеты впереди каждой initiation, `padding` решает паддинг данных, `classify` находит сообщение
  во входящей датаграмме и оставляет его байты как есть (маки считались по ним), `authentic` - о
  подлинных. Ответ `classify` устройство перепроверяет. AmneziaWG - `wg_codec_awg` (`wg_awg.h`), его
  ставит `wg_conf_apply` в память владельца, если параметры файла отличаются от обычного WireGuard.
- У AmneziaWG нет версий: в эталоне это один алгоритм, каждая возможность включается своим параметром
  («1.0», «1.5», «2.0», «3.x» - просто наборы параметров). Все параметры по умолчанию - провод
  обычного WireGuard. Совпадать на двух концах обязаны только S1-S4, H1-H4, HeaderProtectionKey и
  (у принимающего) RandomTrailers; мусор, I-пакеты, паддинг и тайминги у каждого свои.
- `wg_conf_parse` читает `.conf` как wg-quick: ключи без учёта регистра, `#` - комментарий,
  AllowedIPs / Address / DNS складываются, скрипты wg-quick и незнакомые ключи пропускаются с
  предупреждением. Имя в Endpoint остаётся текстом - его разрешает демон; литеральный адрес
  разбирается сразу. `wg_conf_apply` настраивает свежее устройство; при отказе устройство выбросить.
- Тестовый `REQUIRE` вычисляет условие один раз: условие может быть вызовом с побочным эффектом.
  Прежняя версия вычисляла дважды, и повторный вызов тихо заканчивал тест, пропуская 19 проверок. Нашла
  это проверка мутациями - после зелёных тестов её стоит гонять: зелёный набор бывает пустым. Мутант -
  правка КОПИИ исходников по шаблону, и шаблон должен встречаться в файле ровно раз: одинаковые строки
  бывают в двух местах (обнуление узлов в `wg_allowedips_init` и `wg_allowedips_grow`), замена берёт
  первое, и «выжившим» оказывается мутант не того места.
- `stdint.h` из QNX 8.0 при `-std=gnu99` не определяет ни одного макроса пределов и констант
  (`UINT64_MAX`, `SIZE_MAX`, `INT64_C`...) - они есть только с C11. glibc на ПК их даёт, поэтому
  хостовая сборка ошибку не видит. В движке такие значения пишутся явно: `~0ULL`, `(size_t)-1`.
- NaCl box (`wg_salsa`): алгоритм OpenSSL, найденный по имени (`EVP_MAC "POLY1305"`), кросс-линковкой не
  проверяется - имя ищется при запуске. Что он есть в статическом OpenSSL 3.5.8 для телефона, проверено
  отдельно (`configuration.h` без `OPENSSL_NO_POLY1305`, символы `ossl_poly1305_functions` и
  `poly1305_blocks_neon` в бинарнике), а `test_salsa` громко падает, если его нет.
- `wg_box_beforenm` симметричен: обе стороны получают один ключ, поэтому nonce не должен повторяться ни в
  одном из двух направлений - Tailscale берёт каждый случайным, мы тоже.
- Точку малого порядка (`wg_dh` дал нули) `wg_box_beforenm` отвергает, как libsodium; Go `box.Precompute`
  продолжает с ключом, который вычислит кто угодно. Для DERP это значит одно: сервер с таким ключом мы
  не примем.
